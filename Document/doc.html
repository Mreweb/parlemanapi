سند فنی سامانه معاونت پارلمانی ریاست جمهوری با معماری Clean در لاراول و JWT

1. مقدمه

این سند فنی، طراحی و ساختار یک اپلیکیشن وب مبتنی بر Laravel با معماری Clean Architecture را تشریح می‌کند. این معماری با جداسازی مسئولیت‌ها و لایه‌بندی منطقی، توسعه، تست و نگهداری اپلیکیشن را تسهیل می‌کند. اپلیکیشن از JWT (JSON Web Token) برای احراز هویت و مدیریت دسترسی کاربران استفاده می‌کند.

2. اهداف

  • ایجاد یک معماری مقیاس‌پذیر و قابل نگهداری
  • جداسازی منطق دامنه از لایه‌های زیرساختی
  • امنیت و کنترل دسترسی با JWT
  • ساده‌سازی توسعه و تست واحد (Unit Test)

3. معماری اپلیکیشن

3.1 لایه‌ها

  • Entity (Domain Layer): موجودیت‌ها و منطق اصلی کسب‌وکار، مستقل از فریمورک و دیتابیس.
  • Use Cases / Application Layer: قوانین و سناریوهای استفاده، بدون وابستگی مستقیم به UI یا DB.
  • Interface / Adapter Layer: رابط‌ها بین لایه Application و زیرساخت و Presentation.
  • Infrastructure / Framework Layer: پیاده‌سازی واقعی Repositoryها، Serviceها، DB، Mail، Cache و JWT.

3.2 جریان داده

[Controller / Route] → [Use Case / Application] → [Entity / Domain] → [Repository / Infrastructure] → [DB]

درخواست از طریق Controller دریافت می‌شود، به Use Case ارسال می‌شود، منطق کسب‌وکار اجرا و در صورت نیاز با Repository تعامل دارد و داده‌ها از DB واکشی یا ذخیره می‌شوند.

5. JWT و احراز هویت

  • نصب پکیج: tymon/jwt-auth
  • تنظیمات فایل config/jwt.php
  • Middleware برای بررسی JWT در مسیرها

جریان احراز هویت:

  1. کاربر login می‌کند و JWT دریافت می‌کند.
  2. JWT در هدر Authorization: Bearer {token} ارسال می‌شود.
  3. Middleware توکن را بررسی و کاربر را شناسایی می‌کند.

7. پایگاه داده

  • استفاده از MySQL/PostgreSQL
  • جداول اصلی: users, products, orders, roles, permissions

8. نکات امنیتی

  • رمزنگاری پسورد با bcrypt
  • محدودیت تعداد تلاش ورود (Rate Limiting)
  • JWT با تاریخ انقضا و Refresh Token
  • استفاده از HTTPS

9. تست و توسعه

  • Unit Test برای Use Caseها و Entityها
  • Feature Test برای Controllerها
  • Factory و Seeder برای داده‌های تستی

10. بهترین شیوه‌ها

  • جداسازی کامل لایه‌ها و Dependency Injection
  • استفاده از DTOها برای انتقال داده
  • استفاده از Repository Interface برای جداسازی دیتابیس
  • Centralized Error Handling و Exception Handler
